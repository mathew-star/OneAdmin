# ADR-0022: Require a server token for first-run development setup

## Context

Development mode checks the immediate ASGI peer for a loopback address. A local reverse proxy can be that peer even when the browser is remote. Previously, anyone who reached an empty development instance through such a proxy could create its first superuser.

## Options

- Check `Host` as well. A proxy can forward a loopback host, so this is insufficient by itself.
- Remove browser setup and require the CLI. That would make the first local trial more difficult.
- Require a random token generated by the server and printed to its log. This keeps browser setup while requiring access to the server terminal or logs.

## Decision

Each development `AdminSite` generates a random first-run setup token. `POST /auth/setup` requires it and compares it in constant time before creating the account. The login form prompts for the token, which the API never returns. Keep the peer loopback guard as another restriction. Documentation requires binding the server to loopback and avoiding publicly reachable proxies.

## Consequences

First-run setup gains one manual step and a required API field. A development process with multiple workers would generate different tokens; development mode is intended for a single local process. The token appears in server logs, so log access must be restricted. Existing users can continue to sign in without the token.

## Revisit when

If development mode gains supported multi-worker operation, provide one shared setup token through a secure configuration source.
